「一次开发、多端运行」是小程序最吸引人的说法。但真正同时跑微信、支付宝（大陆）、支付宝（香港）几个平台之后就会发现：**API、样式、环境、发布流程，每个平台都有自己的脾气。** 这篇把踩过的坑按「平台 × 维度」整理一下，给同样要做多端小程序的人省点时间。

<!-- more -->

## 微信

### 环境

真机调试有个反直觉的点：**真机调试阶段不校验合法域名、`web-view`（业务域名）、TLS 版本以及 HTTPS 证书。**

这意味着你在真机调试时一切正常，**不代表正式环境就没问题**——上线后这些校验全部生效，域名没配、TLS 版本过低、证书有问题，都会暴露出来。所以别把「真机调试通过」当成「能上线」。

### 发布

微信的发布审核在几个平台里**最严格**，主要卡在两点：

1. **类目审核最严**
   - 解决方案：发布前需要配合后端设置「客制化的审核首页」，让审核能顺利覆盖到对应类目的内容。

2. **合法域名管理最严**
   - 解决方案：发布前务必确认有没有**新增域名**。任何接口、`web-view`、资源用到的域名都要提前加进合法域名白名单，漏一个就会在正式环境请求失败。

## 支付宝（大陆）

### 基础 API

`my.getSystemInfoSync` 在**安卓下不返回 `safeArea`**（安全区域）。如果你依赖 `safeArea` 来做刘海屏/底部安全区适配，安卓上就会拿到 undefined。

- 解决方案：暂时改用 `windowHeight` 和 `statusBarHeight` 自己算，绕开对 `safeArea` 的依赖。

### 样式

**导航栏的返回箭头无法隐藏**（这是平台导航栏的固有行为，详见支付宝小程序的导航相关文档）。设计稿如果假设导航栏可以完全自定义，这里就要和设计对齐预期。

## 支付宝（香港）

支付宝香港版的坑最多，单独拎出来说。

### 基础 API

1. **真机调试时 `my.getMenuButtonBoundingClientRect` 返回的 `right`、`bottom` 值有误。**
   - 解决方案：别直接用它返回的 `right`/`bottom`，改成自己算——`right = left + width`，`bottom = top + height`。

2. **正式环境直接不支持胶囊按钮属性查询 `my.getMenuButtonBoundingClientRect`。**
   - 解决方案：用调试阶段得到的数据，**写一个固定数值兜底**，在该方法不可用时回退到这个固定值。这样真机调试和正式环境都能拿到可用的胶囊位置。

### 样式

1. **导航栏会根据用户手机的不同，时有时无地出现返回箭头**——表现不一致，布局要做好两种情况的兼容。

2. **`gap` 不生效。**
   - 解决方案：改用 `margin` 来做间距，别依赖 flex/grid 的 `gap`。

### 环境

这是最容易翻车的一点：**「开发者工具模拟器」「真机调试 & 预览」「体验码 & 正式环境」是三个互相独立的环境，表现可能完全不同。**

所以**不能只在一个环境里测过就当稳了**，三个环境都要全面自测，尤其是涉及上面那些 API / 样式差异的地方。

### 发布

发布需要**走人工审核流程**。

- 提醒：要注意**节假日的审核排期**（人工审核遇到假期会延迟）。不过实测下来，它其实是几个平台里审核**最快**的——只要避开假期，基本很快就能过。

## 经验总结

把这些坑提炼成几条通用经验：

1. **「真机调试通过」≠「能上线」。** 尤其微信，真机调试不校验域名/TLS/证书，正式环境才全开。上线前一定要按正式环境的校验清单过一遍。

2. **多平台的 API 要做能力探测 + 兜底，而不是假设它都支持。** 像 `safeArea`、胶囊按钮位置这种，平台间差异大，拿不到就用替代方案（`windowHeight`/`statusBarHeight`、固定数值）兜住。

3. **同一平台的不同环境也可能表现不一致。** 支付宝香港的「模拟器 / 真机 / 正式」三套环境就是典型，务必三端都自测，别只信模拟器。

4. **样式属性的支持度因平台而异。** `gap` 不生效就退回 `margin`，导航栏返回箭头不可控就和设计提前对齐——别和平台的固有行为硬刚。

5. **发布流程提前摸清。** 哪个平台审核最严（域名、类目要提前准备）、哪个走人工、哪个会被节假日拖慢，排期时都要算进去。

说到底，小程序的「一次开发多端运行」更多是**结构层面**的复用；落到 API、样式、环境、发布这些细节，**每个平台仍然要单独验证**。把这些差异点提前列成 checklist，比上线后逐个救火要从容得多。
