你正在为本仓库（Hexo + Aurora 个人开发博客）撰写一篇文章。

用户给的原始要点 / 草稿 / 主题：

$ARGUMENTS

请按以下步骤执行：

1. **构思**：把上面的要点扩写成一篇结构完整、可读性强的**简体中文**技术文章。
   - 有清晰的小标题（## / ###），必要时配代码块、列表、表格。
   - 讲清楚「背景 → 问题 → 排查/思路 → 解法 → 经验沉淀」这条线，但不必生搬硬套，自然为主。
   - 语气像开发者写笔记，避免空话套话。

2. **脱敏（强制，最重要）**：绝不能出现以下内容，发现就抽象成通用技术问题——
   - 公司 / 客户 / 内部项目或系统名称、内部域名、内部仓库名
   - 任何内部工单号 / Jira 编号 / 项目前缀（形如 `ABC-1234` 的内部追踪号一律删除或泛化）
   - 真实 API key / token / 密码 / 内网 IP / 数据库连接串
   - 未公开的业务逻辑、架构细节、客户数据
   - 真实人名、邮箱、聊天/截图
   - 代码片段里的内部路径、内部包名
   把「我们公司 X 系统在 Y 单的 bug」改写成「某 Laravel 队列服务遇到的重复消费问题」这种通用表述。

3. **生成文件**：在 `source/_drafts/<英文-kebab-slug>.md` 新建文件（注意是 `_drafts/`，这是 Hexo 的草稿目录，审核前不会上线）。slug 用英文短横线命名。Hexo front matter 格式如下：
   ```yaml
   ---
   title: <中文标题>
   date: <今天日期，格式 2026-06-10 15:04:05，用 `date "+%Y-%m-%d %H:%M:%S"` 取>
   author: xiaoyanger2016
   categories:
     - 开发笔记
   tags:
     - <相关标签>
   ---
   ```
   正文紧随其后。在开头导语之后、正文展开之前插入一行 `<!-- more -->`，用来控制首页摘要的截断位置。

4. **收尾提示**：写完后告诉用户：
   - 用 `hexo server --draft` 本地预览（http://localhost:4000）
   - 自行复核脱敏
   - 满意后用 `hexo publish <slug>` 把草稿移到 `source/_posts/`
   - 然后 `git add -A && git commit -m "post: <标题>" && git push`，GitHub Actions 会自动上线

不要替用户执行 `hexo publish`，也不要自动 push——发布永远由用户在审核后手动完成。
